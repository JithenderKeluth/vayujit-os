# AI Image Studio

AI Image Studio creates immutable, reviewable image outputs from owner-scoped Product Media. It reuses the durable AI Studio job/lease/checkpoint worker and existing Media storage. A generated output always receives its own Media Asset; the source checksum is never overwritten.

## Review and lineage

Outputs expose stable generation/output/Media identity, source IDs, parent output/media IDs, operation, channel, dimensions, MIME, checksum, provider/model, Brand Style and Preset versions, and approval state. The review endpoint is `/api/v1/ai/images/outputs/{outputId}`. Approval and rejection are idempotent and emit safe Audit events without image bytes or secrets. Regeneration queues a new durable job and links the child to the exact parent output.

## Handoffs

Approved outputs can be previewed and confirmed against an owner-scoped Amazon, Flipkart, or Meesho listing. Confirmation requires the preview fingerprint and writes an exact `MarketplaceMediaMapping`; repeated confirmation is idempotent. Campaign handoff stores exact `image_output_id` and `image_media_id` on the Campaign Activity with row-version protection.

## Deterministic provider boundary

`deterministic_mock_v1` is network-free and workflow-oriented. It produces valid PNG fixtures and supports success, throttling, timeout, provider error, invalid image, oversized output, unsupported operation, policy refusal, and crash-after-result scenarios. It does not certify photorealistic quality, live provider behavior, real background extraction, or live marketplace policy compliance.

## Security and privacy

Source Media is owner-scoped and validated by the existing Media service. Generated filenames are server-generated, arbitrary URLs and local paths are not accepted, and provider payloads contain only bounded Product/Brand context and safe metadata. Do not put credentials, buyer data, orders, settlement data, DSNs, or image bytes in Audit events.
## Bulk Images

Use **AI Studio ? Images ? Bulk** or the API plan/queue flow:

- `POST /api/v1/ai/images/bulk/preview` validates Products, channels, operation, dimensions, source strategy, Style/Preset snapshots, limits, and estimated calls without writing rows.
- `POST /api/v1/ai/images/bulk` persists one parent operation and one durable child image job per Product × channel × output index. Reusing the same owner idempotency key returns the same parent.
- `GET /api/v1/ai/images/bulk/{bulkId}` and `/outputs` expose parent progress and reviewable child outputs. Retry/cancel endpoints affect only eligible owner-scoped children.
- `GET /api/v1/ai/images/usage` reports image attempts, generated bytes, latency, and cost as unavailable when no provider pricing is configured. `GET /api/v1/ai/images/diagnostics` reports local provider/storage health without secrets or local paths.

The local deterministic worker is the supported provider for this slice. Run `npm.cmd run test:ai:images:bulk`, `npm.cmd run test:ai:images:usage`, and `npm.cmd run test:ai:images:diagnostics` for the focused acceptance checks.

## Slice 4 certification boundary

The certified local workflow is owner-scoped and durable: source Media is preserved, generated outputs are immutable Media assets with checksum and dimension validation, and each output records exact Product, Content Artifact, Brand Style, and Image Preset versions. The existing AI Studio worker persists leases and checkpoints, recovers crash-before and crash-after-provider cases, rejects malformed or unsafe checkpoints, and keeps retry/cancel operations idempotent.

Review is explicit. Outputs remain pending review until approval; comparison, rejection, regeneration, alt-text suggestion/edit/approve/reject, and history are recorded as safe Audit events. Marketplace handoff requires a fresh preview fingerprint and maps exact Media identity for Amazon, Flipkart, and Meesho. Campaign handoff uses row-version protection. Product Media and Product Channel projections expose downstream usage without copying bytes or credentials. WordPress and Shopify content integrations remain separate and are covered by existing compatibility suites.

Bulk image generation creates one durable parent and one child job per Product/channel/output. Preview is side-effect free, duplicate idempotency keys reuse the same parent, retry/cancel races resolve to one legal durable state, and owner isolation applies to status, outputs, Media, retry, cancel, and approval. Usage reports image modality, operation, provider/model, attempts, latency, bytes, success/failure, retries, and unavailable cost without fabricating token counts. Diagnostics expose local provider capabilities, queued/retry/failed work, storage and cleanup health, and simulated/live state without secrets, DSNs, or local paths.

The deterministic provider is a network-free workflow simulator. It produces valid deterministic fixtures and reports operation honesty metadata: workflow supported and effect simulated. It does not certify photorealistic fidelity, logo preservation, real background removal, or live marketplace policy compliance. Remote/live image providers are architecturally supported but are not validated by this local certification. Promotional creative never invents prices, discounts, coupons, certifications, guarantees, or offers unless canonical input supplies them.

Certification validation uses the disposable PostgreSQL database, migration head, backup tooling, API/worker restart scenarios, checkpoint and storage-integrity checks, focused image and AI regressions, marketplace/campaign compatibility suites, Electron security smoke, Ruff, Black, mypy, frontend build/lint/format, security audit, and performance baseline. Automated axe and viewport harnesses are not configured; keyboard, responsive, and accessibility results must be reported as static/manual validation rather than fabricated automation.
